## 1. Executive Summary & Objective

This specification details the technical architecture for transitioning **EXAMEN** from mock/synthetic sensor indicators to **real telemetry ingestion, rolling performance statistics, and physical Bee wearable device integration**. 

Per architectural directives:
1. **Existing model call signatures and LLM execution nodes remain unmodified** in production code.
2. **Real execution latencies and system telemetry are recorded and aggregated** into persistent SQLite storage (`system_telemetry`), providing live rolling averages (average latency, sample counts, min/max metrics).
3. **The Web UI and Echo Show touch dashboards feature dynamic placeholders and live telemetry bindings**, accurately reflecting edge sensor mesh status, hardware connection states, and backend model configurations.
4. **Hardware integration capabilities of `bee-cli` are fully analyzed**, mapping out what telemetry the Bee Wearable AI platform currently exposes and how EXAMEN bridges ambient hardware into AWS Bedrock AgentCore.

## 2. Bee Wearable AI & `bee-cli` Hardware Integration Analysis

Based on an exhaustive audit of the `bee-cli` source code and documentation ([`resources/bee-cli/`](../resources/bee-cli/) and [GitHub Repository](https://github.com/bee-computer/bee-cli)):

### 2.1 How the Physical Bee Device Communicates
1. **Physical Architecture:** The Bee Wearable is an encrypted personal audio recording device with a 14-day battery life.
2. **Companion Gateway:** The wearable pairs via **Bluetooth Low Energy (BLE)** to the user's iOS or Android companion app. The companion app streams encrypted audio packets to Bee Cloud compute units (`https://app-api-developer.ce.bee.amazon.dev/` or `https://api.bee.computer/`).
3. **Developer Mode & CLI:** The `bee-cli` interfaces with the Bee Cloud API using a bearer token generated by tapping the app version 5 times in Settings (Developer Mode).

### 2.2 Telemetry & Data Capabilities Exposed by `bee-cli`
The CLI client exposes the following commands and real-time events:

| Capability | CLI Command / SSE Event | Payload & Telemetry Extracted | EXAMEN Integration |
| :--- | :--- | :--- | :--- |
| **Authentication & Profile** | `bee status`<br>`bee me --json` | User identity (`first_name`, `last_name`, `id`), API endpoint, auth token validity. | Probes authentication status in `/api/status`, surfacing verified account name (e.g. `Damiano Shushku`) in the System Bar. |
| **Real-Time Speech Stream** | `bee stream --types new-utterance --json` | Utterance text, timestamp, speaker diarization ID (`speaker_1`, `speaker_0`), and `conversation_uuid`. | Ingested by `BeeClient` (`src/ingestion/stream_convo.py`) and buffered by `BeeStreamOrchestrator` (`src/ingestion/orchestrator.py`). |
| **Spatial Telemetry** | `update-location` (SSE)<br>`bee location current --json` | `latitude`, `longitude`, `name`, `address`, horizontal accuracy. | Bound to `LocationTelemetry` in `UtteranceChunk`, informing domestic vs office context. |
| **Speaker Diarization Updates** | `update-utterance` (SSE) | Retrospective correction of speaker labels (`speaker_id`, `utterance_id`). | Retrospectively patched via `ContextRingBuffer.patch_speaker()`. |
| **Conversation Lifecycle** | `new-conversation`<br>`update-conversation` | Conversation start/concluded boundaries, conversation titles. | Informs `SessionManager` macro-session boundary detection. |

### 2.3 Hardware Telemetry Constraints & Suggested Bridge
* **Battery Percentage & BLE Signal (RSSI):** Currently, battery telemetry and direct BLE RSSI metrics are maintained within the companion iOS/Android app and are **not yet exposed as dedicated JSON flags in `bee-cli`**.
* **EXAMEN Hardware State Modeling:** To represent the real state without synthetic mockups:
  - **`STREAMING`:** Live SSE connection established, audio actively streaming, and receiving `new-utterance` events.
  - **`LISTENING (${ACCOUNT})`:** Background orchestrator actively subscribed to Bee Cloud SSE (`bee stream --json`), listening for incoming wearable speech chunks.
  - **`STANDBY (${ACCOUNT})`:** Bee CLI authenticated with a verified user account (e.g. `Damiano Shushku`), idle awaiting stream start.
  - **`DISCONNECTED`:** No valid Bee developer token detected; user prompted to authenticate via `bee login`.

### 2.4 Ingestion Orchestrator Background Stream Management
* **`OrchestratorManager` (`src/serving/mcp_server.py`):** Automatically bootstraps and supervises `BeeStreamOrchestrator` in an asynchronous background task.
* **REST Lifecycle Endpoints:**
  - `GET /api/orchestrator/status`: Real-time stream telemetry, active buffer character length, chunks screened, and heartbeat latency.
  - `POST /api/orchestrator/start`: Starts or restarts the live ingestion stream.
  - `POST /api/orchestrator/stop`: Gracefully suspends background ingestion.
* **Stream Heartbeats:** `src/ingestion/stream_convo.py` extracts raw `{"timestamp": ...}` SSE pings emitted by Bee Cloud, establishing a verifiable connection liveness monitor even before any words are spoken.

## 3. Real Telemetry & Latency Data Architecture

### 3.1 Persistent Telemetry Schema (`system_telemetry`)
In `src/core/storage/sqlite_store.py`, telemetry samples are persisted in a dedicated table:

```sql
CREATE TABLE IF NOT EXISTS system_telemetry (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp TEXT NOT NULL,
    event_type TEXT NOT NULL,
    latency_ms REAL NOT NULL,
    model_id TEXT,
    details_json TEXT
);
CREATE INDEX IF NOT EXISTS idx_telemetry_time ON system_telemetry (timestamp DESC);
CREATE INDEX IF NOT EXISTS idx_telemetry_type ON system_telemetry (event_type);
```

### 3.2 Aggregated Latency Metrics
The storage layer provides `get_latency_metrics(event_type=None, limit=50)` returning:
* `sample_count`: Number of recorded invocations.
* `average_ms`: Rolling arithmetic average latency across the last $N$ executions.
* `latest_ms`: Most recent invocation latency.
* `min_ms` / `max_ms`: Dynamic performance boundaries.

## 4. Sector-by-Sector Frontend Expectations & Placeholder Contracts

The frontend dashboard (`src/web_ui/`) maps backend telemetry to each sector:

### 4.1 System Bar (`src/web_ui/src/components/SystemBar.tsx`)
* **SSE Badge:**
  - `SSE: LIVE STREAM` (green pulsing dot) when EventSource `/api/events` is open.
  - `SSE: CONNECTING` (amber dot) when reconnecting or offline.
* **Bee Hardware Badge:**
  - `BEE: STREAMING` (green active dot) when audio stream is actively ingesting.
  - `BEE: STANDBY (${USER})` (amber dot) when Bee CLI is authenticated as verified user.
  - `BEE: DISCONNECTED` (zinc/gray dot) when unauthenticated or CLI is absent.
* **Bedrock Badge:**
  - `BEDROCK: ${MODEL} (${REGION})` showing active reasoning engine (e.g. `BEDROCK: NEMOTRON (US-EAST-1)`).

### 4.2 Sector 01: Peace of Mind (`src/web_ui/src/components/views/PeaceOfMind.tsx`)
* **Sensor Mesh:** Dynamically bound to `telemetry.sensor_mesh`. Displays `BEE WEARABLE (STREAMING)` if active, or `WEB SIMULATOR / EDGE INGESTION` placeholder.
* **Processing Model:** Displays active `telemetry.processing_model.reasoner` ID (e.g. `NVIDIA.NEMOTRON-SUPER-3-120B`).
* **Latency Overhead:** Dynamically bound to `telemetry.latency.average_ms` formatted as `${average_ms}ms (AVG)`, replacing static `12ms PASSIVE`.

### 4.3 Sector 02: Daily Routines (`src/web_ui/src/components/views/DailyRoutines.tsx`)
* Ingress cadence dynamically bound to sensor mesh state.
* Routine tasks automatically resolve when acoustic actions corroborate completion.

### 4.4 Sector 03: Passive Social Rolodex (`src/web_ui/src/components/views/SocialRolodex.tsx`)
* **Relational Deduplication:**
  - Database-level deduplication on `(contact_name, debtor, description)` in `save_social_commitment`.
  - Contact-level deduplication on normalized `person_name` in `save_social_contact`.
  - Frontend deduplication filter in `SocialRolodex.tsx` guaranteeing zero duplicate cards.
* **Autonomous Web Profiler:** Surfaces verified contact details and executive web dossier.

### 4.5 Sector 04: Topic Dossiers (`src/web_ui/src/components/views/TopicDossiers.tsx`)
* Displays multi-source grounded web citations and deep technical dossiers.

### 4.6 Sector 06: Ambient Simulator (`src/web_ui/src/components/views/AmbientSimulator.tsx`)
* **Transcript Buffer:** Supports multi-lingual transcripts (English, Italian, etc.) with both `transcript_chunk` and `raw_transcript` payload keys.
* **Telemetry Diagnostics:** Displays live execution time (`elapsed_ms`), total recorded runs, and rolling average latency.

## 5. Suggested Model & Backend Optimizations (Non-Modifying Strategy)

In accordance with user directives, **no production model call implementations were modified**. The following optimizations are documented for future implementation:

1. **Italian & Multilingual Gatekeeper Prompt Tuning:**
   - Enhance the few-shot examples in `src/ingestion/gatekeeper.py` to explicitly include non-English colloquialisms for domestic safety (e.g., *"ho staccato il ferro da stiro"*, *"porta chiusa a chiave"*).
2. **Streaming Token Delivery:**
   - Implement SSE token streaming directly from Bedrock Converse API to achieve sub-second TTFT (Time To First Token) for Echo Show displays.
3. **Model Tiering Automation:**
   - Route lightweight classification to **Amazon Nova Micro** (sub-200ms latency, $0.000035/1k tokens) while routing complex topic research to **NVIDIA Nemotron 3 Super 120B** or **Claude 3.5 Sonnet**.
4. **Direct Companion App Webhook Bridge:**
   - Establish a direct webhook bridge (`bee stream --webhook-endpoint <EXAMEN_URL>`) allowing remote edge ingestion without requiring a local terminal session.
